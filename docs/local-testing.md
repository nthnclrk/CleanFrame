# First independent installation

This fork first tests CleanFrame's existing interface. It does not change the
TV's Home button or startup behavior. The upstream layout, wallpapers and
default Home shortcuts are retained; use All apps and Apps on Home to choose
installed services after verifying the app works.

Our package identity was generated by the official Tizen CLI from a basic web
project and applied to the TV manifest without changing its original profile
or required version:

- Package and application IDs: generated by the SDK and saved only in `.local/config.json`
- Display name: `CleanFrame`
- Signing profile: chosen in `.local/config.json` and created with your own Samsung account

Keep these IDs and your author certificate stable for subsequent updates.
`docs/tv-status.md` describes the upstream owner's hardware and installation,
not an independent installation. The native helpers remain upstream's
reference-device implementation. This contribution changes neither native Home
routing nor the helper's firmware/model guards. Their setup, authorization and
recovery remain separate from the app installer; see
`scripts/native-home/README.md`.

For an existing installation, copy its exact package/app IDs into local config
and retain its author certificate and signing profile. Generating a new identity
would create a different app and can break an existing Home assignment.

## Tools and local configuration

The official Linux SDK is installed under `.local/tizen-sdk`. It includes SDB
and the web CLI. Install the Samsung Certificate Extension, Certificate Manager
and TV extensions with its package manager. The development host is Arch based;
Samsung's installer is intended for Ubuntu, so GUI dependencies may require
additional adaptation. No system package changes are included here. The
certificate-manager product was extracted from its official package after
checking the repository SHA-256. The GUI works with a process-specific
HighContrast GTK theme.

Copy `config.example.json` to `.local/config.json`, then fill in the TV address,
SDK path, SDK-generated application identity and signing profile locally. The
loader restricts file permissions to 0600. The example contains placeholders
only; never put a private signing key or password in it.

The source manifest has a generic identity. Packaging substitutes your real
identity directly into the widget archive, without changing tracked source.
The runtime reads its own identity from Tizen for app-list filtering. Keep device information, credentials,
diagnostics and SDK output under `.local/`, never in tracked files. A private
setup record is maintained at `.local/setup-status.json`.

## Samsung certificate

Open `.local/tizen-sdk/tools/certificate-manager/certificate-manager` and add a
Samsung TV profile matching your local configuration. Create your own author certificate,
complete Samsung sign-in yourself, and create a Public distributor certificate
including the target TV's DUID. Keep your author certificate backed up securely.
Use Device Manager's Permit to install applications for the selected TV.

The CLI should list your profile:

```sh
.local/tizen-sdk/tools/ide/bin/tizen security-profiles list
```

Do not send account passwords or certificate passwords through chat. If the SDK
does not retain the signing password, put the certificate password locally in
`.local/certificates/private/certificate-password.txt`, with mode 0600. The
packager uses it only to answer SDK password prompts and redacts it from local
diagnostics. If author and distributor passwords differ, use the SDK's own
profile/password workflow instead of that single-password convenience file.

## Build and test

```sh
npm run check
CLEANFRAME_PUBLIC_FONTS=1 npm run check:browser
npm run check:public
python3 -m unittest discover -s tests -v
npm run package
```

The packager uses public fonts, includes the license notices, and signs through
the official SDK with the owner's profile. For another profile name:

```sh
npm run package -- --profile YOUR_PROFILE
```

Inspect the resulting widget's identity and signatures before installation.
`npm run tv:info` checks the developer connection. `npm run tv:install` and
`npm run tv:launch` install and open the signed launcher. Announce launches to
the owner and confirm the visible result. Keep Home/startup work separate.

Physical checks: rendering, remote navigation, All apps, opening Netflix and
YouTube, then returning through the normal Samsung interface. App launch
callbacks and browser mocks are not physical verification.

See [code quality](code-quality.md) for the automated checks and their limits.

## Git safeguards

`.gitignore` excludes `.local/`, SDK workspace state, certificates, private-key
file types and generated widgets. Only `config.example.json`, containing
placeholders, belongs in Git.

This checkout uses `git config core.hooksPath .githooks`. The pre-commit and
pre-push hooks run the public-source guard, which rejects tracked private paths,
common key files and recognized credential patterns, including staged file contents and reachable Git
history. Enable the same setting after cloning onto another computer. Packaging
also runs the guard. These checks reduce accidental leaks; they do not recognize
every possible secret or prevent deliberately bypassing Git hooks.
