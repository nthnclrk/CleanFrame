# TV compatibility evidence

Updated 2 November 2026. The web launcher has a Tizen 5.0 installation minimum. This admits older packages; it does not establish that every rendering path, Samsung destination or native Home operation works on every admitted TV. Contributor observations and the maintainer’s checks are listed separately. Tizen 4.0 remains an owner-adapted experiment.

Contributor reports have not been reproduced by the maintainer. Browser regression checks cannot verify a TV compositor, native Samsung destination, remote feel or cold boot. The exact Q60B production firmware revision remains to be established: its reported `Version` field was a placeholder, alongside a dated build ID. It is not an exact-firmware allowlist entry.

The AU8000 result used a shell-only helper rather than the maintained .NET 6 helper. Arbitrary shell commands returned `closed`, while the tested `appinstall` argument path still executed as the SDK user and `/usr/bin/aul_test` exposed the needed operation. The contributor reported a brief left-shifted image and misaligned colour channels across Samsung Home and YouTube after applying. Restoring the original values did not clear it; a full power cycle did. The cause was not established. The tested route, symptom and result are specific to that owner’s firmware.

The S85F report used a local guard adaptation for `T-PTMFUABC-0090-1301.0`; the maintained guard still refuses that target. Apps2Samsung is the contributor’s signing route, not a separately reviewed replacement for the official SDK workflow in this repo.

For the LS03F, a blocked execution/readback path stopped the experiment before baseline capture. Its source-resume result is distinct from native app startup. These observations concern that tested route and firmware; they do not prove that every 2025 TV has the same limitation.

## Native Home limits

The maintained helper stays on its reference .NET 6 target and firmware guard. A .NET 3.1 build reported by a contributor has not been checked on the reference TV. Keep generated `bin/`, `obj/`, DLLs and debug symbols private; they can contain local paths and are not reviewed source.

The reference helper requires non-empty original Home and string values. It does not restore absent keys or an initially empty Home operation. Do not substitute Samsung Home for an empty or missing original value. That case needs a reviewed getter/reset contract and a separate reversible experiment.

The [separate LS03T profile](../scripts/native-home/frame-2020/README.md) is experimental, owner-selected source for the reported 2020 firmware. It does not extend the reference allowlist. Its reviewed absent-default contract, source preparation and host policy checks do not establish that the repackaged templates have been deployed. Packaging, model preflight, signing and transport remain owner-supplied.

The reference helper is not Home-only. It accepts an original autostart value of `0` or `1`, requires a current matching snapshot, then enables autostart during apply and handles startup recovery settings. A normal settings change can make a prior query snapshot stale. Do not use that command for a Home-only experiment or treat a changed autostart value as proof of device compatibility.

Apply and restore use the same SDB execution transport. There is no independently verified recovery path if that transport stops working. Query/inspect also upload temporary files. Follow the [staged setup guide](agent-tv-setup-guide.md) under a separate device task, preserve the exact original values, and stop when transport, firmware, runtime, app identity or recovery differs. Keep DUIDs and recovery records private.
