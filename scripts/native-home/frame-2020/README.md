# Experimental LS03T / Tizen 5.5 native integration source

This is a separate reference profile for the reported QE65LS03TAUXXH on firmware
T-NKMDEUC-2743.0. Read [the device report](../../../docs/frame-2020.md) and
[the staged setup guide](../../../docs/agent-tv-setup-guide.md) first.
The existing reference-TV helper and its guards remain unchanged.

This directory contains source templates, an offline preparation tool, and tests.
It does not connect to a TV, sign a package, or install anything automatically.
An owner must separately authorise each device stage. The underlying native
apply/restore flows were checked on the reported TV; the configurable templates
and added baseline-envelope checks have not been redeployed. Offline preparation,
build and policy checks do not verify the native API contract or physical key
behaviour of a newly packaged build.

## Prepare owner-specific source offline

Use two identities generated by the official SDK: the owner's installed web
launcher and a separate optional native Home router. The example identities are
synthetic. Keep real values in `.local/frame-2020.json` and keep certificate
configuration in the existing `.local/signing.json`.

```sh
mkdir -p .local
cp scripts/native-home/frame-2020/profile.example.json .local/frame-2020.json
# Edit only the two identities in the private configuration.
python3 scripts/native-home/frame-2020/prepare.py --config .local/frame-2020.json
```

The script generates source under `.local/frame-2020/`. It validates identities,
requires different launcher/router packages, rejects other profiles and secret
fields, and refuses to overwrite existing output or follow output symlinks.
Preserve an existing generated directory before preparing a different identity.

Build with an SDK that can target `netcoreapp3.0`. The host SDK can be newer than
the TV runtime. Build output, including generated project source and paths, stays
private:

```sh
dotnet build .local/frame-2020/home/Home.csproj -c Release -o .local/frame-2020/home/out
dotnet build .local/frame-2020/startup/Startup.csproj -c Release -o .local/frame-2020/startup/out
dotnet build .local/frame-2020/router/Route.csproj -c Release -o .local/frame-2020/router/package/bin
```

The router package tree contains `tizen-manifest.xml`, a public project icon, and
the compiled `bin/` output. Preparation stops at this tree. The LS03T-specific
TPK packaging, signing, and installation procedure is owner-supplied and is not
recorded in this repository. It must be reviewed before device use. Do not share
the signed TPK.

## Native operation contract

The SDK staging and invocation transport is also owner-supplied and unrecorded
here. Check the live model and review that transport before device use. The existing
`scripts/native-home/run.py` remains scoped to the reference TV; do not remove its
model guard to run these helpers. Query/inspection is itself an authorised device
operation because it stages files.

Stage the selected DLL, runtimeconfig, and deps files in
`/home/owner/share/tmp/sdk_tools/`. Each invocation checks UID 901, ARM32, exact
firmware, and hashes of the relevant native files. Package presence is checked
for apply only, so removal of the launcher cannot block query or restore.
The helpers use these protocol files in that staging directory:

| Helper | Mode file | Private original-state file | Result log |
| --- | --- | --- | --- |
| `CleanFrame2020Home.dll` | `cf2020home-mode.txt` | `cf2020home-original.json` | `/tmp/cf2020home-result.txt` |
| `CleanFrame2020Startup.dll` | `cf2020startup-mode.txt` | `cf2020startup-original.json` | `/tmp/cf2020startup-result.txt` |

The mode file accepts exactly `query`, `capture`, `apply`, or `restore`.
The required helper invocation uses the owner-supplied SDK-user route with
`/usr/bin/dotnet-launcher --standalone`, setting `APP_ID` to the owner's launcher.
This source does not provide a new shell transport or request root.

1. Run `query`. Review the native getter and row evidence.
2. Run `capture` only from the supported original state. Capture uses create-new
   semantics; it refuses to replace an existing original-state file.
3. Pull the original-state file to private local storage. Keep a copy independent
   of SDK temporary-file cleanup. Do not put its contents into an issue or PR.
4. Before each apply or restore, re-stage the matching original-state file.
   Both actions refuse a missing or mismatched baseline.
5. Apply, query again, restore, and query again. Confirm the actual destinations
   with the owner before reapplying. A return code alone is not a screen check.

If SDK cleanup removes the TV's original-state file, restore that exact file
from the private backup before running restore. The captured file is required
evidence of the original state, even where this profile accepts only one value.
Do not reconstruct it from the source constants. If the backup is also lost,
stop and review recovery separately; capture will not replace the original state
with the applied state.

For Home, only the original absent operation is supported. The native getter
must report `-2` with a null app, and the checked operation tables must contain
no matching rows. Other original values require a separate API review. Restore
removes only the selected app's single trial default and checks exact absence;
it refuses unrelated defaults. It opens the databases read-only.

For the first screen, capture records the actual Smart Hub autostart value and
accepts only the reviewed original state. Apply requires a matching captured
autostart value, an installed launcher, and a positive eligibility result. Query
reports unexpected or unavailable first-screen values without a write. Restore
checks the original baseline and current first-screen target, without requiring
the launcher, autostart, or eligibility to remain unchanged. It does not alter
autostart, create missing vconf keys, or combine this with the Home operation.

## Optional signed Home route

The generated manifest declares one short `XF86Home` rule, with the owner's
launcher as its target, and only the public app-launch privilege. It has no
background service. The ordinary `dotnet` app type matches the tested package.
The rule requests the launcher directly; the companion entry point is not a
resident process. The `entry_point:cleanframe_home` marker matches the device-tested
rule. The web launcher does not read that marker; it is retained as request metadata.

Installing this manifest registers its Home rule before any companion C#
entry point runs. The C# firmware guards do not protect installation. The
owner-supplied procedure must check the exact model, firmware, package identity
and recovery route before installation.

Save the original key-rule registry privately before installation. Review the
installed rule, test removal, and compare all affected rows with that original
snapshot before retaining the package. Do not delete Samsung's rule. Removal of
the added router package must precede launcher removal; Home-operation and
first-screen restoration remain separate steps.

## Offline checks

```sh
python3 -B scripts/native-home/frame-2020/check.py
python3 -B scripts/native-home/frame-2020/check.py --dotnet dotnet
```

These checks are run explicitly for this optional profile. The general
`npm run check:tools` command remains unchanged.

The optional .NET check builds all three helpers for their TV target, compiles
the sources for the host, and runs the Home and first-screen apply/restore
policies against synthetic states. It never calls a native TV API.
Tests distinguish absence, empty values, getter failures, another app's
assignment, and unrelated defaults. The Python tests cover identity isolation,
manifest routing/privileges, private output, and overwrite/symlink rejection.
Neither test is a device installation or a broader firmware compatibility claim.
